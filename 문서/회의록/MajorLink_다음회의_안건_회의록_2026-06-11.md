## 다음 회의 안건

### 1. 프로젝트 방향 정리

- MajorLink가 해결하려는 핵심 문제를 다시 정리한다.
- 단순 팀원 모집 게시판이 아니라 어떤 흐름까지 제공할지 결정한다.
- 공모전, 캡스톤디자인, 졸업작품, 사이드 프로젝트 중 가장 먼저 집중할 타겟을 정한다.
- 부산 특화 서비스로 억지 설명하지 않고, 전국 대학생 프로젝트 팀 대상 디지털 플랫폼으로 설명하는 방향을 유지할지 확인한다.

### 2. 기능 추가/제외 정리

- 현재 서비스 안에 꼭 들어가야 하는 기능을 정한다.
- 공모전 제출용으로 강조할 화면을 고른다.
- 지금 단계에서는 빼도 되는 기능을 정한다.
- 구현이 너무 어려운 기능과 MVP에서 가능한 기능을 구분한다.

논의 후보:

- 전공·역할·기술 스택 기반 지원자 비교
- 논문/선행연구 참고 기반 점수 설계
- 프로젝트 종료 후 팀원 동료평가
- 협업 신뢰도 지표
- 프로젝트 완료율
- 프로젝트 종료 합의 리포트
- 직무 전환 희망자를 위한 성장 경로 기반 프로필
- 팀원 초대/친구 초대/계정 연결 기능

### 3. 수익화 방향 정리

- 무료로 제공할 기능과 유료로 전환할 기능을 구분한다.
- 개인 대학생 대상 B2C 모델이 현실적인지 검토한다.
- 학교, 학과, 동아리, 창업지원단 대상 B2B 모델이 더 적합한지 검토한다.
- 프리미엄 모델, 학교 단위 라이선스, 공모전 운영 도구, 동아리/학과 관리 도구 중 어떤 방향이 가장 현실적인지 정한다.
- 공모전 문서에는 과장된 매출 전망보다 초기 MVP 검증 후 확장 가능한 BM으로 표현한다.

### 4. 디자인 방향 정리

- 현재 화면에서 괜찮은 부분과 고쳐야 할 부분을 정리한다.
- 첫 화면에서 바로 보여줘야 할 핵심 기능을 정한다.
- 지원자 비교 화면, 프로젝트 모집 화면, 마이페이지, 종료 평가 화면의 우선순위를 정한다.
- 디자인 톤을 대학생 프로젝트 플랫폼답게 신뢰감 있고 깔끔한 방향으로 잡을지 논의한다.

### 5. 공모전 제출 문서 보완

- 문제 인식이 설득력 있는지 확인한다.
- 해결 방안이 과장되어 보이지 않는지 확인한다.
- 실제 구현된 것과 향후 구현할 기능이 구분되어 있는지 확인한다.
- 선행연구 참고 기반 점수 설계 문장을 어떻게 넣을지 정한다.
- 현재는 정적 HTML 기반 MVP 프로토타입 단계임을 명확히 유지한다.

### 6. 역할 분담

- 발표자료 보완 담당
- 제안서 문장 보완 담당
- 디자인 화면 캡처/수정 담당
- 수익모델 조사 담당
- 경쟁 서비스 비교 담당
- GitHub/증빙자료 정리 담당
- 최종 PDF 병합 및 제출 담당

## 주의할 표현

- `AI 자동 매칭 구현 완료`라고 표현하지 않는다.
- `논문으로 검증된 알고리즘`이라고 표현하지 않는다.
- `국내 최초`, `완전 자동`, `정확한 팀원 판별`처럼 과장된 표현을 쓰지 않는다.
- 현재 단계는 `정적 HTML 기반 MVP 프로토타입/검증 단계`로 표현한다.
- 샘플 데이터는 가상 데이터임을 명확히 한다.
- 실제 개인정보, 연락처, 학번, 서명, 계정 정보는 공개 저장소에 올리지 않는다.
