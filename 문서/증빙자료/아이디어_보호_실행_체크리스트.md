# Campus Link 아이디어 보호 실행 체크리스트

## 목적

이 문서는 Campus Link 프로젝트를 공개 저장소에 보관하면서 아이디어, 기획서, 디자인, 소스코드, 사용자 조사 자료를 어떻게 보호하고 증빙할지 정리한 내부 실행 체크리스트입니다.

이 문서는 법률 자문이 아니라, 공개 자료와 공식 안내를 바탕으로 한 프로젝트 관리용 정리입니다. 실제 분쟁, 출원, 등록, 계약이 필요한 경우에는 변리사, 변호사, 한국저작권위원회, 특허청 또는 영업비밀보호센터에 별도로 확인해야 합니다.

## 기본 원칙

| 구분 | 적용 방향 | 현재 상태 |
|---|---|---|
| 아이디어 자체 | 추상적인 아이디어만으로는 보호가 약하므로 구체적 산출물과 실행 기록을 보관 | GitHub 커밋, 기획서, 발표자료, HTML, 캡처, 해시 보관 중 |
| 저작권 | 기획서 문장, 디자인, 화면, 코드 등 구체적 표현물을 보호 대상으로 관리 | `COPYRIGHT.md`, `LICENSE`, 파일 해시 문서 작성 완료 |
| 특허 가능성 | 기술적 메커니즘이나 BM 특허 가능성은 별도 전문가 검토 필요 | 검토 전, 공개 범위 관리 필요 |
| 영업비밀 | 공개된 자료는 영업비밀 인정이 어려울 수 있으므로 핵심 로직/미공개 전략은 공개 저장소에 올리지 않음 | 공개 저장소에는 발표/증빙용 자료 위주로 보관 |
| 원본증명 | 전자문서 해시와 보유 시점 증명이 필요하면 원본증명 서비스 검토 | 현재는 GitHub 커밋/해시 기반 보조 증빙 단계 |

## 현재 적용 완료 항목

- [x] 저장소에 `All Rights Reserved` 정책 적용
- [x] `COPYRIGHT.md`에 팀명, 팀원, 역할, 보호 대상, 무단 사용 금지 문구 작성
- [x] `LICENSE`에 오픈소스 라이선스가 아님을 명시
- [x] 주요 산출물 SHA-256 해시 기록
- [x] 발표자료, 서비스 기획서, 기획자료, HTML 미리보기 보관
- [x] 실제 서비스 주소와 사이트 캡처 보관
- [x] Google Forms 사용자 조사 결과 캡처와 요약 보관
- [x] GitHub 최초 업로드 시각 기록
- [x] 로컬 HTML 생성/수정일 캡처 보관
- [x] 디자인 시안 작업 과정 캡처 보관
- [x] 공개 저장소에 민감한 계정 정보, API Key, DB 비밀번호, 개인정보를 포함하지 않도록 관리

## 공개 저장소 운영 기준

공개 저장소에는 아래 자료만 보관합니다.

- 프로젝트 소개
- 발표/기획 산출물
- 정적 HTML 미리보기
- 공개 가능한 디자인 시안
- 사용자 조사 결과 요약 및 비식별 캡처
- 제작 시점 증빙 자료
- 저작권 및 무단 사용 금지 문서

아래 자료는 공개 저장소에 올리지 않습니다.

- 실제 서비스 운영 계정
- API Key, Secret, Token
- DB 접속 정보
- 팀원 개인 연락처, 학번, 이메일 등 개인정보
- 계약서 또는 NDA 원본
- 공개 전 특허/BM 검토가 필요한 핵심 기술 구조
- 공개하면 경쟁자가 그대로 구현할 수 있는 미공개 핵심 로직

## 특허 / BM 검토 기준

아래에 해당하면 공개 저장소에 더 자세히 올리기 전에 변리사 검토를 우선합니다.

- 단순 UI가 아니라 기술적 처리 방식이 있는 경우
- 매칭 점수 산정 방식, 추천 알고리즘, 포트폴리오 자동 생성 방식이 독자적인 경우
- 서비스 운영 방식이나 수익 모델이 기존 서비스와 뚜렷하게 다른 경우
- 외부 발표, 공모전, 사업화 전에 권리 확보가 필요한 경우

공개된 발명도 일정 요건을 만족하면 공지예외주장을 검토할 수 있으나, 기간과 서류 요건이 있으므로 전문가 확인이 필요합니다.
